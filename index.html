VesEvoL: Vesicle Evolution over Long time

VesEvoL is a batch image-analysis pipeline for following vesicle evolution over extended time periods. It detects a large "mother" vesicle boundary, detects and locally tracks smaller "daughter" vesicles, quantifies geometry and contacts, and provides downstream plotting scripts for curvature, normalized area, polar/karyograph, and segmentation analyses.

§2 Installation

The pipeline mixes CPU and optional GPU-accelerated libraries. A dedicated conda/mamba environment is recommended — two of the GPU dependencies (tensorflow, cupy) are far easier to get working via conda-forge than pip on most systems.

# create and activate an environment
conda create -n vesicle-pipeline python=3.10
conda activate vesicle-pipeline

# install dependencies
pip install -r requirements.txt

Core dependencies: numpy, pandas, scipy, scikit-image, opencv-python, easygui, matplotlib, alive-progress, trackpy.

Deep-learning segmentation backends: tensorflow (StarDist, default backend), torch + cellpose (optional alternate backend), stardist, csbdeep.

Optional GPU acceleration for mother detection: install a CuPy build matching your local CUDA toolkit, e.g. pip install cupy-cuda12x. Not required — the pipeline detects CuPy/CUDA availability at import time and falls back to a scikit-image CPU path automatically, printing which mode it picked.

§3 Usage

Run the orchestration script directly:

python main.py

It's interactive — easygui dialogs and, for mother-detection parameter tuning, a Matplotlib slider GUI — and will walk you through:

  1. Choosing the folder containing the microscopy stacks to process.
  2. Optionally reusing a previously-defined ROI size.
  3. Choosing Parallel or Sequential execution mode for the whole run.
  4. On the first file, tuning mother-detection parameters (Gaussian sigma, wavelet scale, threshold) live with the slider GUI, then selecting the frame range and spatial ROI.

Per-file output

Each input file foo.czi produces results_v2/foo/:

results_v2/foo/
├── mother.csv                    # per-frame mother-boundary geometry (final)
├── daughter.csv                  # per-frame daughter geometry + contacts (final)
├── detections.npz                # only if SAVE_RAW_NPZ = True
├── mother/
│   ├── mother_metrics.csv
│   ├── raw/, overlay/            # per-frame diagnostic images
│   └── theta_grid_radians.npy, kappa_normalized_vs_theta.npy
└── (segmentation/tracking working folders, overlay PNGs, ...)

Combined summary

After every file in the folder is processed, you're prompted for a name for the combined-results folder:

results_v2/<combined_results>/
├── mother_all.csv            # mother.csv for every file, + a `video` column
└── inner_daughter_all.csv    # daughter.csv for every file, + a `video` column

This step re-reads every per-file CSV back from disk rather than holding all of it in memory during the run, since the per-file CSVs are small (no raw images/masks).

§4 Stage-by-stage flow

Execution mode (Parallel vs. Sequential) is chosen once per run and affects every stage below. Parallel spreads frames across CPU worker processes — faster, but no live progress bar, and GPU segmentation is disabled (a live CUDA/TensorFlow context can't be shared across worker processes). Sequential runs one frame at a time with a live progress bar, and is the only mode that can use a GPU segmentation backend.

1

Load & crop

Read the stack, split into per-frame arrays, crop to a user-chosen frame range and spatial ROI.

main.py → load_stack_efficient(), select_frame_range(), select_roi_per_frame_ranges()
2

Mother detection

Interactively tune Frangi/wavelet/threshold parameters once, then for every frame: gradient/wavelet magnitude → multi-scale Frangi vesselness → skeletonize → contour → shape + temporal scoring. Also computes a per-frame polar curvature profile.

mother_detection.py → MotherTuner.tune(), detect_mother_stack_parallelized()
3

Deconvolution (optional)

Richardson–Lucy deconvolution of the frames, only if SETTING_DECONVULATION = True.

modules/deconvulation.py → gaussian_psf(), deconvolve_frames()
4

Daughter detection & local tracking

Per-frame StarDist/Cellpose instance segmentation restricted to candidates near or inside the mother boundary, filtered by size and circularity. Detections are linked across frames with trackpy, then classified by contact: mother contact (MLS) or daughter–daughter contact (MSS) via nearest-point KD-tree queries.

detect_and_track.py → process_daughters_parallel(), tracking()
5

Compile & write per-file results

Mother and daughter detections are compiled into the final mother.csv / daughter.csv for the file, then every large per-file object is explicitly freed before moving to the next file — so peak memory stays bounded by a single file regardless of batch size.

modules/results.py → compile_experiment_data()
6

Combined summary

Once every file is processed, all per-file mother.csv / daughter.csv are re-read from disk and concatenated into a combined dataset, tagged with a video column.

main.py (end of run)

§5 Configuration flags

Set at the top of main.py.

FlagDefaultEffect
SETTING_DECONVULATION False Run Richardson–Lucy deconvolution on frames before daughter detection.
SAVE_RAW_NPZ False Also cache the raw per-frame image/mask stack to detections.npz. This is the single largest artifact per file in memory and on disk — leave it off unless you specifically need it for offline debugging.

§7 Function reference

Detailed, per-function documentation for all three driver modules. Functions tagged worker run inside a multiprocessing.Pool and aren't normally called directly.

main.py — orchestration

Not a library — run directly as python main.py. Per input file, it:

  1. Loads the stack and splits it into a list of 2-D frames.
  2. Crops to a user-selected frame range and spatial ROI.
  3. Interactively tunes mother-detection parameters once, then runs detection over every frame and saves mother_metrics.csv.
  4. Optionally deconvolves frames.
  5. Runs daughter segmentation + local tracking.
  6. Optionally caches raw frames/masks to disk.
  7. Compiles the final per-file mother.csv / daughter.csv.
  8. Explicitly deletes every large per-file object and calls gc.collect() before the next file, bounding peak memory to a single file regardless of batch size.

After the loop, it re-reads every per-file CSV from disk and concatenates them into a combined summary directory (see Usage).

mother_detection.py — mother boundary detection & tracking

Detects the large "mother" boundary in each frame and scores it against the previous frame for temporal consistency.

Environment setup import-time

  • _autodetect_cuda_path() — if CUDA_PATH isn't already set, scans the default NVIDIA install location and sets it for the current process only (doesn't touch persistent env vars).
  • _register_pip_nvidia_dll_dirs() — registers DLL/.so directories from any pip-installed nvidia-*-cu12 packages so CuPy/TensorFlow can find them.
  • Module-level HAS_GPU probe — compiles a real NVRTC kernel via gaussian_filter, not just a device-visibility check, so it also catches a broken/missing CUDA_PATH.

normalize(img)

Linear rescale of image intensities to [0, 1].

contour_to_mask(contour, shape)

Renders a filled binary mask from a contour array.

compute_circularity(contour)

Isoperimetric quotient 4π·A / P², capped at 1.0.

fit_ellipse_score(contour)

Fits an ellipse via cv2.fitEllipse and returns (aspect_ratio, match_score), where match_score is derived from the mean nearest-point distance between the contour and the fitted ellipse's boundary.

project_curvature_to_theta(kappa, kappa_clean, x_s, y_s, num_theta_bins=360)

Projects a curvature signal defined along arc length onto a uniform [-π, π] angular grid centered on the contour's centroid, handling the periodic wrap seam. Returns (theta_grid, kappa_norm_grid).

cupy_frangi(image_gpu, params)

GPU multi-scale Frangi vesselness filter implemented directly in CuPy — Hessian eigenvalues via a closed-form 2×2 solution, vesselness combining the Rb blob-ness and S structureness terms. Raises if HAS_GPU is False.

score_contour(contour, prev_state, micron_per_pixel, params)

Combines three sub-scores into one detection-confidence value:

  • Shape — circularity + ellipse match, penalized if aspect ratio exceeds ellipse_aspect_ratio_max.
  • Area — soft-clipped around a target size window (defined by min_area_um2 and thresholds at 500/5000 µm²).
  • Temporal — when a previous frame's contour is available, penalizes large centroid jumps or radius changes frame-to-frame.

analyze_mother_frame_gpu_fast(img, micron_per_pixel, params, prev_state=None)

GPU detection path for one frame: Gaussian blur → gradient/wavelet magnitude → cupy_frangi → threshold → skeletonize → contour extraction → score every candidate contour and keep the best. Returns (mother_contour, frangi_u8, skel_u8, intermediates).

analyze_mother_frame_cpu(img, micron_per_pixel, p, prev_state=None)

Same pipeline on CPU: uses modules.image_buildFFT / modules.image_wavelet2d_gauss for the gradient step if available, else a Sobel-based gradient magnitude, and skimage.filters.frangi in place of the CuPy kernel.

ManualCorrector interactive

Matplotlib PolygonSelector GUI for manually drawing a correction contour on a single frame — click vertices, press Enter to commit.

MotherTuner interactive

Matplotlib slider GUI (frame, gauss_sigma, wavelet_scale, threshold_value) for live-previewing detection results before committing to a parameter set for the whole stack. MotherTuner.tune(frames, px) opens the GUI and returns the chosen parameter dict once closed.

_process_chunk(args, bar=None) worker

Runs analyze_mother_frame_gpu_fast sequentially across a chunk of frames, carrying prev_state forward for temporal scoring, and computes each frame's polar curvature profile via curvature_plot_metric.compute_curvature + project_curvature_to_theta.

_save_curvature_worker(args) worker

Per-contour curvature → theta-grid projection, used by save_curvature_parallel.

save_curvature_parallel(results, output_folder, n_workers=2)

Maps _save_curvature_worker over every frame's contour in a small worker pool.

save_mother_results(frames, results, micron_per_pixel, ...)

Writes raw + boundary-overlay PNGs (threaded, not multiprocessed, since it's I/O-bound) and, if save_curvature=True, stacks every frame's (theta_grid, kappa_normalized_grid) into theta_grid_radians.npy / kappa_normalized_vs_theta.npy.

detect_mother_stack_parallelized(frames, micron_per_pixel, params=None, ...)

The main entry point called from main.py. Splits frames into chunk_size-frame chunks and either maps them across a multiprocessing.Pool (parallel=True — faster, no live progress bar) or processes them sequentially in-process with an alive_bar (parallel=False). Returns a dict of per-frame lists (contour, area_um2, radius_um, score, theta_grid, kappa_normalized_grid, ...).

detect_and_track.py — daughter detection & tracking

Detects daughter vesicles near the mother boundary, links them across frames, and classifies their contacts.

save_local_tracking_csv(final_results, output_folder)

Flattens the nested per-frame stats list into daughter_tracking_local.csv.

kdist(m_pts, d_cnt)

Nearest point on m_pts to any point of d_cnt, via scipy.spatial.cKDTree. Returns (min_distance, m_index, d_index).

translate_mask(mask, tx, ty)

Affine-translates a label mask using nearest-neighbor interpolation, to preserve integer labels.

compute_circularity(mask)

Same isoperimetric-quotient metric as in mother_detection.py, computed from a binary mask rather than a contour array.

curvature_radius(contour, idx, k=5)

Local radius of curvature at a contour point, via the Menger curvature of the triangle formed with the points k steps before/after it.

get_contour_points(mask)

Outer contour of a binary mask, as an (N, 2) array.

segment_with_stardist(img_input)

StarDist2D.from_pretrained("2D_versatile_fluo"), with csbdeep_normalize and predict_instances(prob_thresh=0.5, nms_thresh=0.4).

segment_with_cellpose(img_input, use_gpu=True)

CellposeModel(pretrained_model="cpsam"), with flow_threshold=0.4, cellprob_threshold=0.0.

Both backends raise ImportError with the original import error if the optional dependency isn't installed (CELLPOSE_AVAILABLE / STARDIST_AVAILABLE).

save_visuals_robust(output_dir, fname, raw, masks, mother_cnt, mother_radius, daughters_data)

Writes three diagnostic PNGs per frame: the raw image, a clean color-coded overlay of daughter masks, and an overlay with contact-status colors and track-id labels.

save_binary_daughter_sample(base_dir, raw_img, daughter_mask, frame_idx, daughter_id)

Saves a raw-image / binary-mask pair per detected daughter, for building segmentation training sets (save_training=True).

process_frame_worker(args) worker

For one frame: builds a percentile-normalized [0, 1] input image, segments it with the configured backend, keeps only regions within mother_radius + RADIUS_BUFFER_PX of the mother centroid and smaller than half the mother's area, filters by circularity ≥ 0.6, and returns a frame_cache entry plus the frame's detections.

process_daughters_parallel(frames, mother_data, micron_per_pixel, ...)

The main entry point called from main.py. Chooses one of three execution paths based on (parallel, use_gpu):

  • parallel=True → CPU multiprocessing.Pool over process_frame_worker (fastest, no progress bar). Forces use_gpu=False if it was requested alongside parallel=True, since a CUDA/TF context can't be shared across worker processes.
  • parallel=False, use_gpu=False → sequential CPU loop with an alive_bar.
  • parallel=False, use_gpu=True → sequential loop calling the segmentation backend directly on GPU.

If iflocalTracking=True and any detections were found, also runs tracking(...) and writes daughter_tracking_local.csv.

tracking(frame_cache, output_folder, all_detections, ...)

Links detections and classifies contacts:

  1. Links detections across frames with trackpy.link_df (search_range=10, memory=5) and drops short tracks (filter_stubs, threshold=5).
  2. Per frame, translates the mother contour into the frame's local coordinate system and finds each daughter's nearest point on it via kdist; a distance < CONTACT_PX (10 px) marks a mother contact (MLS) and records the local radius of curvature plus a small contour window around the contact point.
  3. For every daughter pair within a frame, runs the same nearest-point check between their contours (per-pair KD-trees) to mark daughter–daughter contacts (MSS).
  4. Emits one row per contact event (MLS/MSS) plus a FREE row for daughters touching neither — each carrying the daughter's contour, centroid, area, and (for contacts) the contact point, and for MSS rows, the id of the other daughter involved.

§9 Plotting & downstream analysis

The supplied archive includes four downstream analysis areas. These scripts operate on processed CSV/results rather than raw microscopy acquisition files.

plot_curvature/

  • plot_curvature_population.py — population-level curvature matrices/figures.
  • heatmap.py — 2-D heatmaps of curvature-related metrics.
  • plot_histogram.py — fitted histogram analysis using dual-Gaussian and lognormal models.
  • divergence_MSS_MLS_Binned.py — binned divergence analysis comparing MSS and MLS metrics.
  • utils.py — dataset-tree parsing, trajectory loading, and 2-minute vesicle binning.

plot_normalized_area/

  • plot_binned_area.py — automatic collection/processing and generation of binned normalized-area figures.
  • plot_single_exp.py — self-normalization, single-exponential fitting, fitted figures, parameter plots, and vesicle-level scatter plots.
  • utils.py — CSV loading, vesicle normalization, time binning, and condition aggregation.

plot_polar/

  • PolarPlot.py — computes contact angles and pairwise geometry and generates polar plots, karyographs, combined karyographs, and contact-curvature figures.
  • Figure-preparation.py — selects experiment/result folders and builds composite figures for figure preparation.
  • mystyle.py / mystyle.mplstyle — plotting style helpers.

plot_segmentation/

  • pipeline_validation_from_csv.py — reads the supplied pipeline_validation_data.csv and compares segmentation-method metrics.
Path configuration. Several plotting scripts contain a local DATA_ROOT or other path configuration pointing to a paper-data directory. Update those paths for the machine on which the analysis is run.

§10 Hardware notes

  • Mother detection — the GPU path requires a working CUDA toolkit and a cupy build matching your CUDA version. The script auto-detects CUDA_PATH on Windows and probes that a CuPy kernel actually compiles (not just that a device is visible) before enabling GPU mode, printing a clear reason if it falls back to CPU.
  • Daughter segmentation — StarDist (TensorFlow) and/or Cellpose (PyTorch), whichever is installed and set as SEGMENTATION_BACKEND in detect_and_track.py (default: "stardist").
  • Multiprocessing — Parallel mode is capped to a small worker count by default to avoid OpenBLAS/BLAS thread-oversubscription crashes on shared workstations; adjust n_workers in the relevant function calls on a dedicated machine with more cores.
